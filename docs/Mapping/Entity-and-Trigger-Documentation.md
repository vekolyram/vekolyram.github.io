# 实体

### Badeline Boost

这就是 Badeline 帮助 Madeline 的方式——字面意义上地给她一个助推。如果单独放置，它会激活"最终助推（final boost）"，用于在原版 Summit 关卡中过渡到下一个检查点。最终助推会让 Madeline 无限向上加速，直到她通过一个画面过渡，或撞到一个 [Stop Boost](#stop-boost) 触发器（或 [Summit Background Manager](#summit-background-manager)）。
如果 Badeline Boost 带有节点，它会将 Madeline 弹射一段较短的距离（可被一次冲刺打断），然后移动到它的下一个节点。
如果启用了 "can skip"，那么每当玩家到达某个节点右侧 100 像素处时，Badeline Boost 球就会移动到它的下一个节点（用于 Reconciliation 检查点，供速通用）。

Badeline Booster 有 3 个与 "Final Ch.9" 相关的选项；这 3 个选项都启用了硬编码到 Farewell 最后一个房间（或金色房间，即 Final Ch.9 Golden Boost 的情形）结尾的行为；Final Ch.9 Boost 会将 Madeline 传送到 "end-granny" 或 "end-golden" 房间，并且除非关卡背景中存在 Blackhole 风格地面（或指定的房间不在地图中），否则会导致游戏崩溃；Final Ch.9 Dialog 会让 Badeline 说 "Say goodbye to her for me"，而 Final Ch.9 Golden Boost 会修改 Final Ch.9 Boost，使其永远不会把 Madeline 送到金色房间。

"Lock Camera" 会让相机永远不向上平移超过 Badeline Boost 当前位置太远。

### Badeline Boss

Badeline Boss 实体从初始模式设定的位置开始，玩家击中她后，她会按顺序遍历她的各个节点。Badeline 有一个很大的碰撞箱，一旦玩家靠近，她会试图稍微远离玩家，不过那种移动纯粹是视觉上的。当她从一个节点移动到另一个节点时，她会破坏路径上的 [Dash Blocks](#dash-block)，并会激活她经过其下方的所有 Badeline Boss Falling Blocks 或 [Badeline Boss Moving Blocks](#badeline-boss)。被击中一次后，Madeline 会被抛向左侧或右侧，具体方向取使她离 Badeline 的下一个节点更远的那一侧。

通常情况下，相机会在 Badeline 下方一定距离内跟随玩家，但不会低于该距离。Camera Past Y 参数控制这个距离（即当屏幕低到 Badeline 允许的最低程度时，从 Badeline 到屏幕顶部的像素距离）。禁用 Camera Lock Y 将完全关闭此行为。

"Can Change Music" 参数控制音乐是否应切换为 Confronting Myself。"Start Hit" 选项让 Badeline 立即移动到她的第二个节点，就像玩家在房间加载的瞬间就击中了她一样。

攻击模式是针对每个独立的 boss 实体设置的。

### Badeline Chaser

Badeline Chasers 会精确地跟随 Madeline 的移动，延迟为 1.55 秒。如果存在多个，后面的会以 0.4 秒的间隔跟在前面那个身后。它们的碰撞箱比玩家的要小得多。如果它们穿越路径上其他本应实心的实体，会直接无视。它们被放置在哪里只决定它们最初出现的位置；它们总是会朝玩家开始移动的地方移动。

![badeline-chasers](https://github.com/EverestAPI/Resources/assets/49392266/0d2a4b54-d3a8-4cd9-8643-71ee714926a9)

### Big Waterfall

这些是大型装饰元素，与它们的较小变体不同，可以水平缩放。此外，与普通瀑布不同，这些实体不在游戏平面上，而是出现在远景（随机视差 -0.7 到 -0.9）或前景（随机视差 0.1 到 0.3）中。

### Bird NPC

根据 Mode 参数的不同，将教程鸟放置到几种动作之一。

设为 None 或 Sleeping 时，鸟会安静地坐着（或睡觉），不与环境互动。
设为 FlyAway 时，鸟会安静地坐着，但当 Madeline 靠近时会飞走。
设为 MoveToNodes 时，鸟的行为与 FlyAway 类似，但每次 Madeline 靠近时，它都会栖息到下一个节点的位置，飞完最后一个节点后飞走。
设为 ClimbingTutorial、DashingTutorial、DreamJumpTutorial、SuperWalljumpTutorial 或 HyperjumpTutorial 时，鸟会叫唤并显示与原始 Celeste 中相同的对应教程信息。Climbing、Dream Jump 和 Super Wall Jump（这是开发者对 wallbounce 的称呼）模式在某些条件下也会让鸟飞走。
最后，在 WaitForLightning 模式下，鸟会原地盘旋，看起来十分焦虑，直到房间的闪电被移除；随后鸟会向上飞出屏幕。（游戏代码中有个东西控制鸟是否垂直移出屏幕；不过这个值只会被原始过场所设置）

如果勾选了 Fly Away Left 复选框，那么当 Madeline 在鸟右侧的位置重生或进入房间时，鸟不会出现。如果设置了 Only Once，且鸟的模式是 MoveToNodes，则鸟在从最后一个节点飞走后不会重生。

仅在 Super Wall Jump 模式下，如果 Madeline 在鸟的位置下方 4 个图块以上处重生或进入房间，鸟不会出现。

如果把 Bird NPC 放在移动物体顶上，它们会附着到移动物体上。

### Bird Path

玩家进入房间时，蓝鸟会沿着实体节点指定的路径飞行。节点数必须为偶数（不计实体本身），否则游戏会崩溃。鸟的速度可以调整，也可以设置为仅在玩家从实体左侧进入房间时才激活。

![bird-path](https://github.com/EverestAPI/Resources/assets/49392266/6d75052c-e380-432d-820a-342a76255aed)

### Bonfire / Campfire

篝火，例如 Madeline 在遗弃之城（Forsaken City）结尾过场中点燃的那堆。它们没有游戏性用途，但可以当作装饰元素使用。
这些实体有一个参数，用来设置篝火在视觉上是点亮（Lit）、冒烟（Smoking）还是未点燃（Unlit，完全静止）。如果篝火设置为 Lit，且地图的元数据启用了 "dreaming" 参数，火焰会像古址（Old Site）开头那样呈绿色。

![campfire](https://github.com/EverestAPI/Resources/assets/49392266/facaabcd-8ca1-43b7-b331-b936a1c65f7d)

### Booster (Green / Red)

因其外形常被称为泡泡。玩家进入其中一个后，经过 15 帧的延迟或按下冲刺键，玩家会朝着其按住的方向被向前助推，距离约为一次普通冲刺（6 个图块），速度为每秒 240 像素。在此状态下，玩家如果直接接触地面可以跳离，接触墙壁可以 wallbounce，可以破坏 [Dash Blocks](#dash-block)，或者（原版中见不到，但自定义地图中可行）激活 Kevins 或穿过 Dream Blocks。

红色 Booster 会无限持续下去，而不是在 6 个图块后停止，甚至能穿过画面过渡。它们仍会在玩家死亡、与另一个物体或实心物体互动、或冲刺出去时消失。风会影响这些 Booster 的轨迹。

![green-booster](https://github.com/EverestAPI/Resources/assets/49392266/ac5e7c0b-7917-4181-b0bd-2f8b2dcc9a37)
![red-booster](https://github.com/EverestAPI/Resources/assets/49392266/59b72843-89b5-45fc-84d6-977a17a6e814)

Booster 包含一个参数 "Ch.9 Hub Booster"。该参数用于原版的一个 Booster（Farewell 中 Power Source 枢纽的红色那个），负责处理与过渡到 Remembered 检查点相关的、主要是视觉上的行为。如果玩家使用该 Booster 向上移动，且房间内没有已存在或被锁定的 [Lock Blocks](#lock-block)，玩家在其路径结束前将不允许从 Booster 中冲刺出来，并且会启动用于 Remembered 过渡的音乐时间线。这些 Booster 还会修改 Tag 为 "bright" 的风格地面的不透明度，并在某些情况下影响关卡的光晕（bloom）。

> [!WARNING] 小心
> 这里记录 Ch.9 Hub Booster 功能只是为了完整性，但建议永远不要将其用于自定义关卡，除非是要完全重现 Farewell 中使用的那个子区域过渡。这些 Booster 的效果非常特殊且令人困惑，如果需要，几乎所有效果都可以用其他方法实现。
>
### Bridge

这是序章（Prologue）的桥。它的长度可以设置，并带有两个红色"标记"，用于标出桥上一个既有破洞的位置。其他行为（例如玩家相对其最左端的位置应如何才能让它开始崩塌，以及结尾提前塌落的那一段）都是硬编码的。桥的崩塌速度与玩家自身速度相关。

![Bridge](https://github.com/user-attachments/assets/40044ce8-c902-4b11-8b99-6e02c3ebc535)

### Bridge (Fixed)

序章桥的装饰性修补版本，不会崩塌。它的精灵图是按段绘制的，但碰撞箱只延伸到实体的长度（所以请仔细确认二者匹配！）。

![Fixed Bridge](https://github.com/user-attachments/assets/35fa9c50-8b6e-4f74-910a-e49e27288bbf)

### Bounce Block / Core Block

如果 Core 模式是 None 或 Hot，玩家抓住它或落到其顶上时，它会稍微回缩，然后朝着玩家相对其中心（以中心的菱形标记）的方向"弹跳"，只有当玩家在它"弹跳"时起跳才会获得助推，之后它会碎裂。

如果 Core 模式是 Cold，它则会改为开始非常缓慢地下沉约 1.25 秒，然后崩塌。

无论 Core 模式如何，当方块碎裂后，它会在 96 帧（1.6 秒）后重新成形。如果玩家、[Pufferfish](#pufferfish)、可持物、[Seeker](#seeker) 或实心物体在 Core Block 试图重新成形时位于其位置内，Core Block 会延迟重新出现，直到障碍消失，然后立即重新成形。

Core Block 有一个参数：Not Core Mode，它让方块*始终*表现得像 Core 模式为 Cold 一样。

![core-block](https://github.com/EverestAPI/Resources/assets/49392266/66e11951-928c-4b55-9ad4-f8c296773d29)

### Bumper

玩家可以与它们互动，这会把玩家从相反方向"弹开"。它们空闲时会轻微"晃动"（水平与垂直方向），这确实会影响它们的碰撞箱。如果玩家从 Bumper 的某个侧面击中它，并在冻结帧期间（或互动的那个帧）按住自己将被弹向的方向，会被弹得更远。

Bumper 没有参数，但最多可以有 1 个节点。带节点的 Bumper 会在其位置与节点之间来回移动。
此外，Bumper 会对关卡的 Core 模式做出反应。如果 Core 模式是 None 或 Cold，Bumper 会如上所述工作；如果是 Hot，Bumper 会变红并在接触时杀死玩家。

![bumper](https://github.com/EverestAPI/Resources/assets/49392266/40010496-4321-43f7-8bac-815a867257ca)

### Cassette

这些实体用来为关卡的门 B 面把关。收集后，游戏会停下、播放一段过场，然后带着玩家穿过各个节点，直到到达最后一个节点，泡泡破裂，玩家恢复自由。收集它会禁用整个关卡中所有的 cassette blocks，强制它们关闭并停止交替。

> [!NOTE] 说明
> 如果在恰好的时机收集卡带，某一种颜色的 cassette blocks 可能会卡在 On 状态，直到房间重新加载。如果你设计的房间在玩家收集卡带后仍可能涉及 cassette blocks，请留意这一点。
>
![cassette](https://github.com/EverestAPI/Resources/assets/49392266/7d888c51-b2fa-458c-b3e4-2afbf51dccfd)

### Cassette Block

这些方块会随着音乐的节拍从背景中弹进弹出，变成实心方块。有 4 种颜色可用，不过 Farewell 之外只用到了 2 种。Cassette Blocks 总是按 Blue、Pink、Bright Sun（黄）、Malachite（绿）的顺序循环。房间加载时，cassette blocks 会尝试让 Blue 方块先处于 On 状态。任何附着在 cassette block 上的实体都会随方块一起出现和消失，附着的 [spikes](#spikes) 和 [springs](#spring) 会与方块的色彩匹配。如果两个同色方块相邻，它们在视觉上会连成一体。如果玩家在 Cassette Block 弹出的瞬间从其上面跳起，会跳得比平时更高。

![cassette-block](https://github.com/EverestAPI/Resources/assets/49392266/e3bc7a44-5df9-4e06-9620-d57c23d3d563)

### Chaser Barrier

这些不可见的矩形区域会让 Chaser 一旦进入就停在原地，做一个"大笑"的动画，然后过一会儿消失。用于古址（Old Site）Badeline 追逐的结尾。

![chaser-barrier](https://github.com/EverestAPI/Resources/assets/49392266/f9e540b7-9698-4344-b985-4b466d9da452)

### Clothesline and Cliffside Flags

这些是类似 [Wire](#wire) 的装饰实体，包含挂在线上的一些矩形布块。除布块颜色外两者几乎完全相同，而 Clothesline 的布块通常更大。与 wire 不同，这两个实体都不受 [Wind](#wind) 影响。

![clothesline](https://github.com/user-attachments/assets/517e8919-2110-40f5-b9ef-addd6760f36a)
![cliffside-flags](https://github.com/user-attachments/assets/084b3d10-612b-4cc5-9221-0c63410b1d47)

### Cloud and Fragile Cloud

云彩是可弹跳的平台，如果 Madeline 在弹跳的最高点起跳，可以获得助推。"Fragile" 选项会让云彩变成粉色，一次弹跳或跳离就会使其碎裂（不过它们仍会补充冲刺）。Fragile Clouds 会在 2.5 秒后重新出现。普通云彩的碰撞箱宽 32 像素；小型云彩的碰撞箱为 26 像素。由于云彩本质上属于半实体平台，可以把尖刺附着在它们上面。

> [!TIP] 提示
> 如果你的关卡是从原版 .bin 文件的副本制作的，请注意原版关卡中的云彩被硬编码为在 B 面中只能是小型。如果直接编辑 .bin 文件，所有云彩都不会是小型，就像其他原版 bin 中的 spinner 颜色一样需要手动更改。
>
![cloud](https://github.com/EverestAPI/Resources/assets/49392266/bc3f03a7-cb86-483d-bb81-de7f69b30246)
![fragile-cloud](https://github.com/EverestAPI/Resources/assets/49392266/524b3788-4935-4b05-86cc-77e801e52d71)

### Clutter Block, Cabinet, Door, and Switch

有 3 种类型的 clutter blocks，每种都配有自己的 Clutter Switch。Clutter Blocks 单独使用时用于阻挡路径或构成平台。

一旦 Clutter Switch 被激活，所有与之绑定的 clutter blocks 都会被收集走，清空它们阻挡的东西。Clutter Switch 的按压状态会一直保持到章节结束或被重置。

还存在第四种 Clutter Switch 类型，在原版中未使用，它上面有闪电标志，并且会像（设置了 Flag 属性的）[Breaker Box](#lightning-breaker-box) 一样清除 [Lightning](#lightning)。

> [!WARNING] 警告
> 在没有 Clutter Cabinet 的房间中使用 clutter switch 会导致游戏崩溃。"Lightning" 型开关不在此列。
>
Clutter Cabinet 是特定 Clutter Switch 激活后所有 clutter blocks 被吸进去的地方。

Clutter Door 会在特定 Clutter Switch 被激活后阻挡玩家进入某条路径。在原版中，Oshiro 会打开这些门，但只会打开你还没做过的那部分。这种门也存在 "Lightning" 变体。

![clutter-cabinet](https://github.com/EverestAPI/Resources/assets/49392266/b9a5b1d5-d4d8-4710-afb0-1faf3ee98d02)
![clutter-door](https://github.com/EverestAPI/Resources/assets/49392266/913c7b8b-f488-4866-bf91-ec6087a41548)
![clutter-switch](https://github.com/EverestAPI/Resources/assets/49392266/8a0ae79f-7dcc-4d3a-917a-13ce1abf0905)

### Cobweb

蜘蛛网是 [Wires](#wire) 的一种变体，可以有任意多个节点。蜘蛛网实体的两端构成"主"线，看起来像普通 Wire。所有其他节点对应额外的蛛丝，从各个点附着到主线上并伸向节点。与 Wire 一样，蜘蛛网可以重新着色，不过侧面的蛛丝总是比主线略深。如果蜘蛛网的某个节点在其房间加载时没有接触实心物体，它的整根侧蛛丝都不会出现；如果该节点对应主线，则整个实体都不会出现。原版游戏利用这一点来制造出随着 [Clutter](#clutter-block-cabinet-door-and-switch) 被清除、空间变得更干净的效果。与 Wire 不同，蜘蛛网的任何部分都不受 [Wind](#wind) 影响。

![cobweb](https://github.com/user-attachments/assets/0ca7d9c6-21d9-4254-8840-e0e8bfa2ca3d)

### Condition Block

它们的工作原理与 [Exit Blocks](#exit-block) 类似，但只有在条件满足后才会变成实心。这些条件可以关联到钥匙、草莓或按钮（dash switches）。条件以 `房间名:实体id` 的形式设置（例如 `00-a:413`）。如果在房间加载时，游戏识别到指定房间中具有指定 id 的那种实体已被收集，方块就会是实心的。为防止软锁，建议让 Condition Block 延伸覆盖过场过渡。这样，玩家过渡时它还不实心，而是在玩家离开其碰撞箱后才出现。

> [!TIP] 提示
> 在编辑器 Lönn 中，右键点击实体时弹出的窗口中，顶部可以看到实体的 id。
>
### Core Mode Toggle

这些双心形开关在 Hot 与 Cold 之间切换 Core 模式，反之亦然。它们可以设置为仅切换到 Cold、仅切换到 Hot，或 Both。如果开关设置为只切换为一种模式，那么当那种 Core 模式正生效时它就无法使用。如果设置为 Both，它可以在两种 Core 模式间来回切换，但只有在其 1 秒冷却结束后才能再次使用。所有类型都会立即改变 Core 模式，从而改变所有受 Core 模式影响的实体。如果勾选 "Persistent"，死亡不会把 Core 模式恢复为按下开关之前的状态。

![core-mode-toggle](https://github.com/EverestAPI/Resources/assets/49392266/dd789e0c-8289-45c2-81b0-6f9af91122b0)

### Cover-Up Wall

与 [Fake Walls](#fake-wall) 完全相同，只是玩家进入其中时它不会消失，也不会播放"秘密被揭晓"的音效。原版游戏中很少使用。

### Crumble Block

这些平台一旦被互动（无论是落地还是抓住）就会开始崩塌。如果落在上面，它们会在 0.6 秒（36 帧）后消失，或者在你跳起、冲刺或滑离的瞬间立即消失。如果抓住它们的侧面，它们总是会在 1 秒的超时后消失，在此期间你仍可以跳上或跳下。它们会在 2 秒后重新生成。
它们有一个贴图参数，可以设置为 2 种原版贴图变体，或[与 Jump Throughs 类似的自定义贴图](Reskinning-Entities.md#跳穿平台)。

![crumble-block](https://github.com/EverestAPI/Resources/assets/49392266/0e8a3538-7d87-4b26-a797-c8cf0ddce596)

### Crumble Wall On Rumble

如果某个 [Rumble](#rumble) 触发器被激活，且其节点在水平方向上涵盖了方块的位置，这些方块就会崩塌。Tiletype 参数决定方块以哪种图块集显示，Blending 参数勾选后会让方块与附近墙壁融合（参见 [fake walls vs fake blocks](#fake-block)）。Persistent 参数会让方块在被摧毁后保持消失状态，即使房间被重置。

![crumble-wall-on-rumble](https://github.com/EverestAPI/Resources/assets/49392266/619cd582-1ca1-4c14-961f-8878c64f9e83)

### Crystal Heart

更严肃的收集品。玩家碰到它时会弹开并恢复冲刺。冲刺撞上它或向它投掷 [Theo Crystal](#theo-crystal) 会让它碎裂，玩家会在一段短过场后收集它，之后玩家被冻结在原地，章节的水晶之心诗篇台词出现在屏幕上。玩家在这段收集过场中仍然可能死亡，那样不算收集成功。

在原版 A 面中，Crystal Hearts 通常非常隐蔽或难以到达。在原版 B 面和 C 面以及 Core 中，它们被用作章节的结尾。玩家每面关卡只能收集其中一颗，即使地图中放置了更多颗。

在元数据菜单中，有一个选项可以让收集 Crystal Heart 算作章节结束，类似 Core 或 B/C 面。如果启用该选项，击碎水晶之心还会立即"收集"所有仍在跟随玩家的草莓，即使玩家随后死亡。

如果勾选 Fake，Crystal Heart 会呈现灰色，并在收集时启动第 9 章的相关场景。场景开始不久，会播放 Fake Heart Dialog 参数指定的对话 ID，对话结束后，水晶之心图形会碎裂，然后播放 Keep Going Dialog 参数指定的对话 ID。

![crystal-heart](https://github.com/EverestAPI/Resources/assets/49392266/d8336ed1-677b-47cb-97b2-7fd0c17e4f24)

### Crystal Heart (Dream)

一种装饰性实体，外形是无形、幽灵般的（仿佛在水下）水晶之心。这颗心永远是蓝色的，无法以任何方式互动。

![dream-crystal-heart](https://github.com/user-attachments/assets/1887a332-55db-4395-81d5-eda9b41ad19d)

### Crystal Heart (Fake)

不要与 Farewell 中出现的假 [Crystal Heart](#crystal-heart) 混淆，这是一个外观和行为与普通 Crystal Heart 完全相同的实体。唯一区别是当玩家"收集"这颗心时，不会播放过场或给予收集品，心只是消失，并恢复玩家的冲刺。它会在 3 秒后重新出现。Fake Hearts 有一个选项，可以决定复制 A 面、B 面或 C 面 Crystal Hearts 的外观，或是每颗心在这三者中随机一个；无论关卡的真实之心如何，Fake Heart 都会是所选的颜色。

### Crystal Spinner / Dust Bunny

这些是最常见的障碍物之一，尤其从天界度假村（Celestial Resort）起。它们的碰撞箱[长这样 :link:](https://github.com/EverestAPI/Resources/assets/52103563/86ea4472-77f4-4d74-8c40-1a77e72e06c0)：中间有一个比精灵图略小的主圆形碰撞箱，以及一个横跨中心、高 4 像素、长 16 像素的第二个矩形碰撞箱。如果 2 个 Spinner 放置得足够近，它们会通过在两者之间覆盖没有碰撞箱的特殊背景精灵图来在视觉上连接起来。
6 种 spinner 分别是 Blue/Red/Purple spinners（纯色、不变色）；Core spinners（对关卡当前的 Core Mode 作出反应）；Rainbow（用于 Farewell，带有从关卡原点径向发散出的绿/蓝/紫渐变）；以及度假村中使用的 dust bunnies。全部 6 种类型的碰撞箱完全相同。

如果勾选 "Attach to solid" 参数，spinner 会尝试附着到其碰撞箱内的任何移动实体上。勾选了此参数的 spinner 在视觉上不会与未勾选该参数的 spinner 相连。如果两个都设置为附着的 spinner 附着到了不同的物体上，视觉连接只会跟随两者之一，这通常是不希望看到的。

通常建议在可能时将 spinner 吸附到图块网格上，因为不这样做可能导致若干种轻微的视觉或游戏性差异（例如因为矩形碰撞箱最终陷进地里，导致能在方块边缘站上几像素）。同样最好避免过于密集地放置 spinner，使它们的主要精灵图相互重叠。

如果将两个 spinner 上下放置、相距两个图块、并对齐网格，两个 spinner 之间的空间刚好（4 像素）够玩家在两者之间做一次 demodash。

![dust-bunnies](https://github.com/EverestAPI/Resources/assets/49392266/fe0bbacd-8797-44d9-8631-38650ce11733)

### Dash Block

能被冲刺或其他特殊条件破坏的方块。能够破坏它们的实体或条件包括：玩家的冲刺、移动中的 [Kevin](#kevin-crush-block) 方块、下落中的 [Falling Blocks](#falling-block)，或处于任一颜色 [Booster](#booster-green-red) 内的玩家。

如果禁用 "Can Dash"，玩家的冲刺不再能破坏方块，但其他一切仍然可以。勾选 "Permanent" 意味着方块被摧毁后保持破碎状态，即使在重生之后；不勾选则方块在每次重生后重新出现。"Blending" 意味着如果它与 Foreground 图块接触，会看起来像是墙的一部分（参见 [fake walls vs fake blocks](#fake-block)）。

![dash-block](https://github.com/EverestAPI/Resources/assets/49392266/9a96ebdb-7a04-4251-87c6-1c6c755aa624)

> [!NOTE] 说明
> 上图中方块上的裂缝部分是一种叫 "Object Tiles" 的东西。这是一种非常罕见、在原版游戏中很少见的东西，在 Ahorn 中与 Entities 分开，目前也不在 Lönn 中提供。建议使用带 `overlay` [Decal Registry](Decal-Registry.md) 属性的自定义贴花来模拟这种行为。
>
### Dash Switch

这些开关按钮会在玩家冲刺撞上时激活。它们也可以被 [Theo Crystal](#theo-crystal)、[Seeker](#seeker) 或快速移动的 [Jellyfish](#jellyfish) 激活。激活时它们会打开最近的关闭中的 [Temple Gate](#temple-gate)（该门必须处于 "nearest switch" 模式）。
如果启用 "Persistent" 属性，按钮会保持按下状态，并在玩家死亡或重新进入房间时被视为已激活。
如果启用 "All Doors" 属性，该 touch switch 会打开房间中所有设置为 "nearest switch" 的 temple gates。
Dash Switches 有一个 sprite 参数，仅影响视觉，可以[与 Jump Throughs 类似地修改](Reskinning-Entities.md#跳穿平台)。

> [!NOTE] 说明
> Persistent dash switches 一旦被激活，房间重新加载时最近的（temple gate）门会处于打开状态。这未必是当初用这个 persistent switch 打开的那扇门！
>
![dash-switch](https://github.com/EverestAPI/Resources/assets/49392266/41bb805a-5d30-471d-a1de-e23c03cdd31c)

### Door & Trapdoor

门是一种装饰性实体，Madeline 靠近时打开，离开时关闭。可以通过在门的路径上放置实心物体来阻止门打开，门也会被移动的物体推动（因此可以附着到 [Floaty Space Blocks](#floaty-space-block) 上）。有木质和金属两种。

活板门（Trapdoor）是旋转了 90 度的门变体。Madeline 穿过时它们向下扇动。活板门不会被推动，也没有金属版本。

![Door](https://github.com/user-attachments/assets/73c884de-7edc-4bb4-96b4-71760c46c404)
![Trapdoor](https://github.com/user-attachments/assets/397f3749-ffa3-4035-9647-431818f82d20)


### Dream Block / Space Jam

这些方块出现在古址（Old Site）和山巅（Summit）1000M 的各个地方。虽然它们的外轮廓看起来在流动移动，但碰撞箱始终不变。它们是实心的，所以玩家可以爬上爬下、踩在上面。玩家冲刺撞入时，会沿进入方向穿过，直到从另一侧出来。在这种状态下玩家可以穿过 Foreground 图块，但如果撞到会致死的碰撞箱，仍然会死。此外，如果玩家从梦块中出来时正好进入实心物体，会被"挤压"致死（除非是另一个 dream block，那样会继续前进）。

如果玩家按住与移动方向相反的方向并按住抓取，从方块出来时会抓住它（如果另一侧没有尖刺），除非方块只有一个图块宽且玩家是水平冲刺的，那样不会抓住。玩家可以从 dream blocks 里跳出来，也可以从里面 hyper 出来（这会消耗玩家的冲刺）。

Dream Blocks 可以有一个节点。带节点的 Dream Blocks 会缓慢地往返于其位置与节点之间。勾选 "Fast moving" 会让这些方块移动得更快。勾选 "One use" 会让 Dream Block 在玩家出来后消失，但这种消失没有动画，所以很少使用。"Below" 属性会让 Dream Block 渲染在离前景稍远一点的"深度"，这意味着它不会遮挡其下方的一些物体，比如 [Refills](#refill)。

在关卡的元数据中将 "inventory" 设置为 OldSite，会在章节开始时冻结所有 Dream Blocks，冻结期间无法冲刺穿过它们，它们也不移动。当玩家激活 Dream Mirror 或某个改变玩家 inventory 或显式激活梦块的触发器时，它们会解冻。

![dream-block](https://github.com/EverestAPI/Resources/assets/49392266/5d69eea6-d904-4a26-aa56-e17ee11db984)

### Exit Block

如果玩家不在其碰撞箱内，这些实体会变成实心。通常用于阻挡回头路。

### Fake Block

与 [Fake Walls](#fake-wall) 完全相同，只是它接触 Foreground 图块时不会融合。[Fake Walls](#fake-wall) 在大多数情况下比 Fake Blocks 更受推荐。

![fake-wall-fake-block](https://github.com/user-attachments/assets/29bd1543-fe5f-4182-865c-ce5dbec24773)

### Fake Wall

这些实体从远处看像实心墙，但没有实心碰撞箱。如果它接触 Foreground 图块，会与墙壁"融合"。玩家进入其中后它会消失，露出它覆盖的一切。
Fake Walls 无法堆叠，因为其他墙的边缘仍然会露出来。Fake walls 还会显示在 Foreground Decals 之上，所以被 Fake Wall 半遮住的 Foreground Decal 可能暴露秘密。还建议将 fake wall 的尺寸设为覆盖秘密缺口周围的两个墙图块，因为 Celeste 拼图的一部分如果不被覆盖也可能暴露秘密。

![fake-wall](https://github.com/EverestAPI/Resources/assets/49392266/cae25c47-bdf8-4025-92f1-6a642e6b2c73)


### Falling Block

这些方块正如其名，被互动后就会下落。如果你落在顶上或抓住其侧面，它会在 0.6 秒（36 帧）后下落，如果你松开或滑落，它立即下落。这些方块以每秒 160 像素的速度下落，可以破坏 [Dash Blocks](#dash-block)，并会一直下落直到离开屏幕或撞上 Foreground 图块、其他实心实体。如果它落到的东西移动或从其下方掉落，它会继续下落。也可以禁用 "climb fall"，使它只能从顶部或其他实体（如 [Kevins](#kevin-crush-block)）触发。"Behind" 属性控制方块的视觉深度，意味着一些其他实体会渲染在它之上，而不是被它遮住。
当 [Badeline Boss](#badeline-boss) 飞过其水平位置时，falling blocks 也会被激活。

> [!NOTE] 说明
> 虽然大多数实体只在玩家与它们同处一个房间时才会加载，但 Foreground Tiles 不受此限；因此地图制作者应注意确保非常高的 falling blocks 不会砸到地图的其他部分上。用某种图块实体替换有问题的图块，或用大量危险物遮住墙上的洞，都是不错的变通方法。
>
![falling-block](https://github.com/EverestAPI/Resources/assets/49392266/1b9ff6d6-792f-4b97-8445-ed28fcc546a6)

### Feather

玩家碰到羽毛后，会进入一种持续移动的状态，直到 2 秒后羽毛超时，或玩家落地、抓住墙壁、冲刺离开、或死亡。飞行过程中碰到另一根羽毛会重置计时器。收集后，羽毛会在 3 秒后重新出现。羽毛被认为是最难稳定操控的机制之一（至少对经验不足的玩家而言），因为它的移动接受模拟输入。它的运动会受到风的影响。

如果带护盾，羽毛会被包裹在泡泡里，玩家可以在泡泡上弹跳以获得冲刺补充，或者冲刺进去打破护盾拿到羽毛。如果勾选 "One Use"，羽毛使用后就不会再出现。

![feather](https://github.com/EverestAPI/Resources/assets/49392266/93c33286-34b7-4c6e-b48d-e673e392a93c)

### Fire Barrier / Ice Block

这些实体根据 Core 模式激活。Fire Barriers 在 Core 模式为 Hot 时出现，Ice Blocks 在 Core 模式为 Cold 时出现。两种类型都不会在 "none" Core 模式下出现。它们的所有面都能杀死玩家，但它们的 killbox 内部有一个实心碰撞箱，意味着玩家可以借此进行墙壁跳跃甚至 wallbounce（只要他们距离方块大约 1-3 像素）。

![fire-barrier](https://github.com/EverestAPI/Resources/assets/49392266/264069d6-f563-4a60-b125-d7133468eed3)
![ice-block](https://github.com/EverestAPI/Resources/assets/49392266/a0c3a99b-f161-4109-935d-13dfc3793cb1)

### Fireball / Ice Ball

如果 Core 模式是 Hot 或 None，它们是接触即死的火球。如果 Core 模式是 Cold，或设置了 "Not Core Mode"，它们会冻结，变成更慢的 Ice Balls。在这种状态下，玩家可以跳到其中一个上面，这会让 Ice Ball 碎裂消失（如果 Core 模式切回 Hot，它会保持消失）。除顶部外，其他所有面仍会像平常一样杀死 Madeline。
火球和冰球都有一个比其精灵图略小的常规圆形碰撞箱；冰球会额外获得一个供玩家弹跳的水平碰撞箱。

如果放置时没有节点，这些实体将保持静止。如果有节点，它们会以常规速度遍历所有节点，并且可以穿过 Foreground 图块。可以使用 Amount 参数在同一条轨道上放置多个火球。Offset 参数延迟周期的"起点"；偏移 0 与偏移 1 相同。它们的基础速度由 Speed 参数设置。

![fireball](https://github.com/EverestAPI/Resources/assets/49392266/e67b1083-0a23-4fd2-9669-969d3ba1f4bf)
![ice-ball](https://github.com/EverestAPI/Resources/assets/49392266/00964c97-e6bb-48bd-a2a2-e035357ee40d)

### Floating Debris

每一块漂浮碎片都是单个仅装饰用的小块岩石，悬浮在半空中。Madeline 靠近时，漂浮碎片会稍微移动。

### Floaty Space Block

这些方块带着随机偏移缓慢上下悬浮，Madeline 站在上面时会略微下沉，如果冲刺撞入，它们会短暂地朝冲刺方向移动然后返回。相邻的 Floaty Space Blocks 会自动合并成一个相连的方块，[Jump Through](#jump-through) 平台会粘在它们上面。

> [!WARNING] 小心
> 如果两个相连的 floaty space blocks 彼此"齐平"（也就是说，你可以同时站在或抓住两者），两个方块都会对受该方块影响的任何碰撞箱施加作用力。最明显的表现是玩家抓住一个 floaty space block 的两个相连齐平部分的侧面时（玩家会随着方块漂浮被向上或向下拉动），但玩家冲入方块也可以影响放在方块上的实体，例如 jellyfish。floaty space blocks 重叠的表面也有同样的行为。

### Ghost Player Playback

Madeline 的单色影子版本，原版中用于辅助讲解 Farewell 里的 wavedashes。该实体有一个参数，可以挑选播放哪个教程（每个都是预先录制的 Madeline 输入序列）。虽然可以实现自定义播放，但原版选项包括 Event Horizon 早期看到的 3 个教程，以及 wavedash.ppt 中的那些（例如演示按跳跃键太晚会发生什么的教程）。此实体常与 [Playback Billboard](#playback-billboard) 配合使用，但那只是视觉上的。

### Glass Block

在原版 Celeste 中未使用，这些方块带有晃动的星光贴图，接触音效与 [Starjump Blocks](#starjump-block) 相同。相邻的 Glass Blocks 会在视觉上合并，与 [Starjump Blocks](#starjump-block) 和 [Floaty Space Blocks](#floaty-space-block) 类似。Glass blocks 有一个叫 "sinks" 的参数，但它什么都不做。

### Golden Block

在原版 Celeste 中未使用。最初是为 Farewell 的 [Golden Strawberry](#golden-strawberry) 设计的，但后来被最终的 [Badeline Boost](#badeline-boost) 金色房间取代。如果 Madeline 携带 [Golden Strawberry](#golden-strawberry) 且距离其左侧边缘不到 80 像素，它们会从底部滑入到位。踩上去时它们会下沉，与 Starjump Blocks 类似。

![golden-block](https://github.com/EverestAPI/Resources/assets/49392266/84f3ec7f-34f5-41f9-8998-be942d7feb06)

### Golden Strawberry

在"无用收集品"的意义上，它们与草莓几乎相同。不过，这些草莓通常位于章节开始时玩家上方。它们可以通过 [Golden Strawberry Collection](#golden-berry-collection) 触发器收集，该触发器通常放在关卡结尾；不过在关卡被清空（例如用 Complete Area 触发器）时它们也会自动收集。如果玩家带着一颗死亡，它会被送回收集该草莓的位置；如果放在第一个房间，还会重置关卡计时器。

Golden Strawberries 只会在模组关卡中出现在以下情况：A. 关卡合集中的每个关卡都有 B 面，且合集内每个 B 面都已被通关；或 B. 关卡合集中并非每个关卡都有 B 面，且每个 A 面都已被通关。无论哪种情况，如果关卡本身尚未通关，它们都不会出现（C 面相关时需要注意）。

> [!NOTE] 说明
> 就金色草莓而言，`complete` 调试命令似乎不算作通关该关卡。
>
如果玩家没有收集金色草莓，在关卡的其他房间死亡，然后返回第一个房间，金色草莓会消失。

> [!WARNING] 警告
> 如果 Golden Strawberry 不在玩家打开关卡时出生的那个第一个房间中，那么玩家在收集它之前死亡时它*不会消失*。如果玩家可以在关卡中取得有意义的进展后回到那个点，就不要把金色草莓放在非第一个房间！
>
如果使用 "Winged"（有翅膀的）Golden Strawberry，它会像普通带翅草莓一样飞走（它没有任何其他效果或生成条件）。如果 Golden Strawberry 是 "No Dash" 变体，它只会在玩家整个关卡中完全没有冲刺过的情况下出现。这种变体通常出现在关卡结尾，比如原版遗弃之城（Forsaken City）A 面。
Golden Strawberries 与原版游戏一样有 "Moon" 参数；这些参数没有游戏性效果，但会把视觉改成与原版 moonberry 完全相同（收集时音效不会独特，也不会出现分数点）。

![golden-strawberry](https://github.com/EverestAPI/Resources/assets/49392266/a21b49e9-a188-4cc6-abe3-a640de567397)

### Gondola

缆车（gondola）是一种基本属于装饰性的实体，用于黄金山脊（Golden Ridge）的一段过场。没有那段过场就无法让它移动。
该实体有一个主放置位置和一个节点，各自对应缆绳的一端。它只有一个参数 "active"，用来切换缆车应出现在放置位置还是节点处。如果在节点处，缆车的操纵杆会缺失（因为这是镜之圣殿（Mirror Temple）中看到的实体版本）。缆车的地板是它唯一的实心表面。

### Heart Door

这些是阻挡进入第 8 章、其 B 面和 C 面，以及第 9 章后三分之二进度的门。Requires 参数决定玩家需要收集多少颗 [Crystal Hearts](#crystal-heart) 才能打开门。如果勾选 Start Hidden，门最初会隐藏，当玩家在水平方向上离它 12 个图块以内时轰然落下。落下的 Heart Door 会摧毁其路径上的任何 [Dash Blocks](#dash-block)，并且是唯一能在辅助模式（Assist Mode）下杀死 Madeline 的东西。

### Intro Car

Madeline 在序章（Prologue）中的汽车。车顶和引擎盖可以站立，有趣的是，弹簧和尖刺会粘在上面。如果勾选 Has Road And Barriers，序章中的道路和护栏会随汽车一起生成。

### Intro Crusher

序章（Prologue）第一个屏幕中的下落方块。当被接近（超过左侧边缘 30 像素，或距右侧边缘 8 像素）时，它会开始震动 1.2 秒，然后在 1 秒内移动到其结束位置。如果玩家提前离开它（距右侧边缘 8 像素，或距其左侧边缘 28 像素），震动会提前结束。

### Invisible Barrier

正如其名：它们能阻挡玩家，因为它们是实心的，但不可见。原版中经常用在屏幕外阻挡回头路（比如 Badeline 战斗中）。它们也用于阻止非预期路线，例如阻挡玩家用 demodash 跳过镜之圣殿（Mirror Temple）的 "Search" 检查点提前见到 Theo。

下面这张 Lönn 预览图显示了一个 invisible barrier 阻挡玩家在原版 Mirror Temple A 面中回头。请注意，该 barrier 被放置并加载在右侧房间中，尽管它被放在"界外"、即左侧房间占用的空间里。这样，左侧房间加载时玩家不会撞到它，但进入右侧房间时也不会卡在里面。

不知何故，如果 invisible barrier 放置得能让玩家站在上面，它就会使用 deadgrass 图块集的脚步声。

![在 Lönn 中看到的 Invisible Barrier](https://github.com/user-attachments/assets/7d23b8b1-f9b3-41c7-a445-b5c1540b6bf9)

由于 Madeline 无法从 Invisible Barriers 上抓取、攀爬或起跳，它们也可以放置在实心方块内部，来制造具有这一特性的可见方块（它们的碰撞箱可以完全重叠，这个效果仍然有效）。*然而*，建议改用 Extended Variants 模组，以更优雅的方式在整个关卡中实现这一点；否则，应注意确保可抓取墙与不可抓取墙之间有明显、一致的区别。

与图块实体类似，如果某个 Invisible Barrier 会让玩家在进入房间时卡在里面，它就不会加载。

### Jellyfish

Jellyfish 像 [Theo Crystals](#theo-crystal) 一样可以携带，但要飘浮得多，让 Madeline 可以手持它缓慢向下滑翔。按住上可以略微减小下落速度，按住下可以增加。与 Theo Crystals 一样，Jellyfish 可以激活 [Touch Switches](#touch-switch) 和 [Dash Switches](#dash-switch)。如果在冲刺期间冲刺撞入并抓住它们，会沿冲刺方向获得显著助推。如果存在向上的风，jellyfish 会默认向上漂浮，即使 Madeline 正抓着它。如果勾选 Tutorial，jellyfish 会显示一个教学框说明如何抓握它；如果勾选 Bubble，它会生成在一个脆弱的蕾丝平台上，在 Madeline 抓住它之前不会掉落。最后，如果 Jellyfish 碰到 [Seeker Barrier](#seeker-barrier)，它会碎裂，在房间重置之前不会重生。

![jellyfish](https://github.com/EverestAPI/Resources/assets/49392266/35224ad0-0214-4df4-8884-0d343b072f1a)

### Jump Through

游戏中随处可见的这些平台让玩家可以穿过其底部并安全落在顶部。常用于向上画面过渡、空中尖刺和单向通道。如果玩家被移动的实心物体（如 [Kevin](#kevin-crush-block) 或 [Falling Block](#falling-block)）挤向它，玩家会穿过平台掉下去而不是死亡。你也可以在正好位于平台顶部的状态下退出羽毛状态时穿过它们。

![jump-thru](https://github.com/EverestAPI/Resources/assets/49392266/b38d52e7-3d58-4470-bb76-19d67e345a4c)

### Kevin / Crush Block

尽管代码称它们为 Crush Blocks，但大家都叫它们 Kevins，以纪念 Power Up Audio 的 Kevin Regamey——他提供了它们激活时使用的声音。Kevins 可以激活两个移动轴中的一个或两个。如果玩家冲刺撞入 Kevin 的某个已激活轴，它会以每秒 240 像素的速度沿该方向无限移动，破坏 [Dash Blocks](#dash-block) 并忽略 [Spinners](#crystal-spinner-dust-bunny)，直到撞到实心物体。一旦撞到东西，它会沿着来时的路径试图返回其原始位置。Kevin 的移动可以在任何时刻被撞中其另一个尚未激活的"enabled"轴或侧面打断，然后它会朝那个方向移动。如果 Kevin 在"攻击"期间撞上 [Falling Block](#falling-block)，falling block 会下落。

Kevins 把房间的顶部和侧面当作边界，但仍会自由地从房间底部出去（如果发生这种情况就不会回来了）。
在"攻击"期间，Kevin 可能被慢速移动的实心物体"推动"。Kevin 的返回路径由它每次转弯 90 度各点之间的距离决定，所以这样推动 Kevin 会使其静止位置发生偏移。Kevins 在返回路径上能够穿过实心物体。

如果勾选 "Chillout"，Kevin 无法被打断，也不会尝试"返回"运动。如果向右移动，Chillout Kevins 会在接近目的地时减速（这种行为在房间布局不同时似乎有些不一致）。如果 Chillout Kevin 在两个方向上都超过 6 个图块长，游戏会认为它是"巨大"的，并将其硬编码为无论启用哪些轴都只能成功向右移动。

![kevin](https://github.com/EverestAPI/Resources/assets/49392266/4e518910-e594-488b-91d8-6d9fa6059090)

### Kevin's PC

一个藏在 Farewell 中的彩蛋和 ARG 步骤，模组中很少使用。Kevin's PC 是一个不影响游戏性、会在玩家靠近时播放非常响亮的持续噪音的实体。它会附着到放置在其下方的任何 [Floaty Space Block](#floaty-space-block) 上，并且可以在其底部中心被其他移动方块推动。

### Key

一旦收集到一把钥匙，它会一直跟着你，除非你使用它，即使你死了也一样。你甚至可以在拿到钥匙的瞬间暂停并重试，仍然会保留它。它们只能打开 [Lock Block](#lock-block)。Key (with return)（带返回的钥匙）在被收集时，会把 Madeline 放进一个泡泡里，沿着钥匙的节点移动，直到到达最后一个节点，她才会被放下。

![key](https://github.com/EverestAPI/Resources/assets/49392266/7b5b2bb1-f112-4632-8066-a9270cbf9a91)

### Killbox

"Killbox" 这个名字其实是个误称。Killboxes 并不是看起来那样的、玩家一进入就会死亡的死亡矩形。相反，它们充当半动态的死亡平面。如果玩家不直接位于 Killbox 水平跨度上方，它什么也不做。如果玩家位于该区域上方，它就会承担关卡死亡平面的角色，锁定相机，并像房间底部一样杀死掉得太低的玩家。

Killbox 的死亡屏障与房间底部的死亡屏障有几点不同。Killboxes 只影响玩家；某些通常不能低于房间的实体（如 [Kevins](#kevin-crush-block) 或 [Seekers](#seeker)）会忽略该屏障的效果。此外，Madeline 在死亡前可以深入房间底部下方很远，但在 Killbox 屏障下却连一像素都踏不出去。

下面，可以在关卡编辑器 Lönn 中看到一个 killbox，如果玩家掉落，它会阻止玩家掉入关卡下方区域很远的地方。

### Lamp

Lamp（路灯）是装饰性灯柱。如果设置了 Lamp 的 Broken 参数，它会显得杂草丛生且不发光；否则它会显得干净并发光。

![Lamp](https://github.com/user-attachments/assets/a40c175f-7093-4da7-9d3d-837b10a8c0a5)

### Lightning

Lightning 是一种拥有完全实心碰撞箱的危险物，与 [Crystal Spinners / Dust Bunnies](#crystal-spinner-dust-bunny) 的碰撞箱相反。如果有节点，它会在节点间来回移动，移动时间由 Move Time 参数（以秒为单位）决定。与 [Floaty Space Blocks](#floaty-space-block) 类似，相邻的 lightning 实体会在视觉上连接起来（即使两块闪电移动不同的距离等等）。

Per Level 参数控制 Lightning 对 [Lightning Breaker Boxes](#lightning-breaker-box)（设置了 Flag 参数的）被破坏的反应。如果未设置 Per Level，且这样一个 Breaker Box 被破坏，该 lightning 将永远不会再生成（想想 Power Source 的闪电）。否则，闪电只对房间中 Breaker Box 的临时状态作出反应（想想 Reconciliation 的闪电）。

> [!NOTE] 说明
> 如果 lightning 实体相互重叠，重叠区域会略微——但可见地——更不透明。因此，要让一组跨越房间过渡的闪电看起来好看是非常困难的。没有 helper mods 的话没有好办法。
>
![lightning](https://github.com/EverestAPI/Resources/assets/49392266/b4d1a1c5-96af-4745-a09b-f43aaba8a172)

### Lightning Breaker Box

被冲刺撞击两次后，这些箱子会消失并杀死房间中任何 [Lightning](#lightning) 实体。第一次撞击不会恢复玩家的冲刺，但第二次会。勾选 Flag 框时，breaker box 会在被摧毁时激活闪电禁用标志，永久从地图中移除任何未勾选 Per Level 框的闪电实体。勾选 Flip X 时，breaker box 的精灵图会水平翻转。

Music 和 Music Progress 参数用于在 breaker box 被摧毁时修改音乐。在 Lönn 中，Music 参数使用与关卡元数据中的 Music 设置相同的格式。如果启用 Music Session，音乐的任何变化都会在玩家死亡后保持。

![lightning-breaker-box](https://github.com/EverestAPI/Resources/assets/49392266/d2ee008e-340a-4f2e-a918-e19e8600e9ed)

### Lock Block

这些门只能用 Key 打开，你足够靠近时就会打开。一旦打开，就会一直保持打开，即使你死了。
钥匙要开始开门，玩家需要处于距门约 32 像素的圆形半径内，且两者之间没有实心物体。解锁动作大约在钥匙在视觉上进入锁孔时变为永久。

### Moon Creature

Moon creatures 是微小的团块，四处漂浮，Madeline 靠近时会试图跟随她。它们纯粹是装饰性的。如果调整 "Number" 参数，单个 moon creature 放置可以生成多个生物。

![moon-creature](https://github.com/user-attachments/assets/f5fc151e-e97a-4cc2-8441-23272587caee)

### Move Block

这些方块会以每秒 60 像素的速度，朝其中间箭头指示的方向开始移动。它们以恒定速度移动。如果 "Fast Moving" 为 true，它们会改为以每秒 75 像素移动。如果设置为 "Steerable"，它的一个或两个侧面（与箭头垂直的面）可以被抓住或站立，让玩家能一定程度上操控方块（玩家可以在上/下移动时使方块左右移动，或在左右移动时使方块上下移动），只需在骑乘时使用方向输入。

如果 Move Block 撞到实心物体，玩家有 9 帧时间引导它转向以让它继续前进；否则它会在 12 帧后崩塌。崩塌后，它们会在 3 秒后于原始位置重新生成。与 [Core Blocks](#bounce-block-core-block) 一样，Move Blocks 在有东西阻挡时不会重新生成。
在罕见的随机情况下，Move Block 自身的碎片会阻止它重新成形。

由于 Move Blocks 在撞到非常边缘的位置时倾向于避开实心方块进行角落修正，它们可以被慢速移动的实心物体在与运动垂直的方向上"推动"。

![move-block](https://github.com/EverestAPI/Resources/assets/49392266/ec75c747-87ea-4fe7-b938-2e4b989de9b6)

### Moving Block / Badeline Block

这些方块在被特定的 [Badeline Boss](#badeline-boss) 节点激活后，会从原始位置移动到节点再返回。当 [Badeline Boss](#badeline-boss) 再次被击中时，它们会碎裂。

![moving-block](https://github.com/EverestAPI/Resources/assets/49392266/fc03b080-2e23-4be0-bafd-cbd4b8a764bf)

### Moving or Spinning Blade, Dust Bunny and Star

它们沿设定路径移动，无论路径是圆形还是来回直线。它们的碰撞箱与 spinner 相同，只是圆形的没有第二个矩形碰撞箱。如果圆形移动刀片（blade）的中心位于移动实体内部，旋转刀片会随其一起移动。设置为 "Dust" 或 "Star" 只会改变它的外观/音效。
移动刀片有一个 "speed" 参数，不过这些速度略反直觉：Slow 刀片移动 0.9 秒、暂停 0.3 秒；Normal 刀片移动 0.4 秒、暂停 0.2 秒；Fast 刀片移动 0.3 秒但暂停 0.6 秒（长得多！）。旋转刀片完整转一圈总是需要 1.8 秒，所以其速度取决于半径。

![moving-dust-bunny](https://github.com/EverestAPI/Resources/assets/49392266/cd14fc4a-8659-41d6-9579-732ca6354955)

### Moving Platform

### Oshiro Boss

Oshiro 在屏幕左侧生成，并在垂直轴上跟随玩家。经过一段设定时间后，他会锁定并向前冲锋。在此期间，他有一个致命碰撞箱，但玩家可以跳到他的头上，这会立即将他制服，并返还一次冲刺。他冲出屏幕后（无论是一次冲锋后还是被跳到头上后），会重新出现。他可以通过这个实体或相应的触发器激活。

在 A 面中，他重生后锁定和冲锋所需时间有一个模式：1 秒、2 秒、3 秒、2 秒、3 秒。在 B 面和 C 面中，始终是 1 秒。

### Plateau

这是第 6 章"坠落"过场使用的装饰性实体。它是一段宽阔的水平地面，高度略小于一个图块。它的碰撞盒在图形两侧各提前一个图块结束。

### Player (Spawn Point)

这些实体定义玩家死亡后会在哪里重生。画面过渡时，游戏会选择离玩家最近的那个作为出生点。

[Change Respawn](#change-respawn) 触发器会把出生点改为距离触发器中心最近的 Player 对象；如果触发器有节点，则为距节点最近的那个。[Respawn Target](#respawn-target) 与带节点的 [Change Respawn](#change-respawn) 触发器行为相同，但有两个关键区别：它们只在玩家过渡时激活，并且即使玩家在新房间的第一帧暂停并重试，它们也仍会设置玩家的出生点。

当前的出生点不会在没有过渡或触发器的情况下自动更新，即使玩家穿过了某个 Player 对象。

> [!IMPORTANT] 重要
> 如果一个房间内没有 Player 对象，游戏不会让玩家进入该房间。
>
### Pufferfish

Pufferfish 是一种发射型实体，可以从上方弹跳将其压下去约 8 个图块，也可以被弹簧向上/向侧方弹起。此外，如果玩家进入 pufferfish 下半部周围的标记半径内（且不在某个实心物体的另一侧），它会爆炸，将玩家弹离，然后在 2.5 秒后重生。与 [Bumpers](#bumper) 类似，如果玩家在 pufferfish 爆炸时按住自己将被弹射的方向，会被弹得更远。同样与 Bumpers 类似，Pufferfish 会以影响其碰撞箱的方式晃动。

如果勾选 Right 参数，pufferfish 会面朝右，但这只是视觉变化。

![pufferfish](https://github.com/EverestAPI/Resources/assets/49392266/e408958a-cedf-459b-8eb7-203a6b7e2f14)

### Refill

这些水晶会恢复玩家的冲刺和体力。如果你在还有冲刺但体力耗尽时碰到一个，会消耗它来恢复体力。如果你冲刺穿过一个，或在冲刺后碰到一个，会恢复体力和冲刺。如果你天生有两次冲刺，只使用一次冲刺仍然会消耗这个补充物，而使用两次冲刺则会恢复两次冲刺。如果你有临时的第二次冲刺，普通补充物只能通过低体力被消耗。勾选 "One Use" 会让补充物使用后不再出现，直到重生或画面过渡。勾选 "Two Dash" 会在收集时给 Madeline 一次一次性的第二次冲刺。通常，它们会在 2.5 秒后重生。

### Rising Lava / Ice

如果放在某个屏幕中，只要玩家不在 Lava blocker 触发器（Everest 自带）内，熔岩就会以稳定的速度从屏幕底部上升，接触即死（不过它的碰撞箱比屏幕上看到的熔岩略低）。如果 Core 模式设置为 Ice，它会变成冰，但其余功能完全相同。

如果相机向上平移，熔岩会继续在屏幕外上升。如果屏幕侧向平移，熔岩会随屏幕移动，因为它没有被编程为横向滚动。原版游戏中所有使用此机制的核心（Core）屏幕宽度都是默认的 40 个图块。

> [!TIP] 提示
> 上升熔岩会"橡皮筋"运动，也就是说如果它出了屏幕会移动得更快。因此请注意关卡的相机：如果相机偏移过高，熔岩几乎总在屏幕外，这会比你预期得难得多！
>

### Sandwich Lava / Ice

如果放到一个屏幕中，熔岩会出现在屏幕底部和顶部。顶部和底部会以与普通上升熔岩相同的速度上升。如果 Core 模式设置为 Cold，熔岩会冻结，并开始以与上升的冰类似的速度向下下降。这会迫使玩家不断前进并激活不同的 [Core Mode Toggles](#core-mode-toggle)，以避免熔岩升得太高或冰沉得太低。

相机可以无碍平移，不过原版游戏中所有使用此机制的核心（Core）屏幕高度都是默认的 23 个图块。

![sandwich-ice](https://github.com/EverestAPI/Resources/assets/49392266/2f0cffa1-0965-452b-8b15-a04eaba9e8d7)

### Seeker

来自镜子的怪物。一旦发现玩家，它们会锁定并冲过来。它们通常直线冲锋，但如果玩家移动也可能转弯。如果冲锋中的 Seeker 撞上 [Temple Cracked Block](#temple-cracked-block)，方块会碎裂。Seekers 也能收集 [Touch Switches](#touch-switch)。如果 Seeker 处于 [Seeker Barrier](#seeker-barrier) 内，它会无视玩家，而 Seekers 无法穿越该屏障。

玩家可以跳到这些 Seekers 的头上，这会让它们下落一段距离、改变外观，并在约 2.65 秒内变得不可触碰，之后它们恢复正常，并带有一道短冲击波，可以破坏附近的 [Temple Cracked Blocks](#temple-cracked-block)、推动 [Theo Crystals](#theo-crystal)，并给玩家一股动量助推。Seekers 可以通过挤压杀死（但如果玩家死亡或离开屏幕，它们会重生）。如果 Seeker 丢失玩家的视线，它会返回原始位置，然后开始沿基于其节点的路径巡逻。如果 Seeker 的巡逻使它撞进墙里，它只会待在那里直到下次看到玩家。

![seeker](https://github.com/EverestAPI/Resources/assets/49392266/c982c2d4-a935-43e2-82ab-cbac1b00a387)

### Seeker Barrier

这些半透明屏障有流动的轮廓，但碰撞箱是平整的。如果两个或更多 Seeker Barriers 相邻，它们会"合并"。由于它阻挡 Seekers 穿过，它为玩家创造了安全区域。如果 Seeker 被放置在 Seeker Barrier 内部，它会完全无法移动，但仍可以跳到它头上。Seeker Barriers 还会让 [Jellyfish](#jellyfish) 一接触就碎裂。

> [!TIP] 提示
> 虽然看起来不像，但 Seeker Barriers 算作实心物体，Spikes 或 Springs 之类的东西可以附着到它们上面，这可能会产生一些非常令人困惑的行为。如果尖刺错误地附着到了 seeker barrier 上，可以通过选中、剪切并把 seeker barrier 粘贴到同一位置来修复（这会让 seeker barrier 在附着方面的"优先级"变低）。
>
![seeker-barrier](https://github.com/EverestAPI/Resources/assets/49392266/f436145e-d9f6-479d-91f7-6bdf0fdc0b5e)

### Slider

Sliders 是一种未使用的危险物类型，轻而易举地是原版中最不稳定的实体；如果不理解其行为，它们几乎必然会触发 Everest 的崩溃处理器（如果不是直接硬锁游戏的话）。

Sliders 呈一个巨大的红色圆形，危险碰撞箱只比它稍小一点。它们粘在实心物体的边缘上，试图沿其外轮廓追踪路径（根据需要粘住地板、墙壁和天花板）。对 Sliders 而言，Jump Throughs 及相关半实体物体不算实心。如果 slider 的路径带它离开屏幕边缘，它不会卸载，而是继续在尽可能多的关卡 Foreground Tiles（它们是全局加载的）上沿路径前进，直到回到起始位置。不过 Madeline 离开房间时，Sliders 仍会像平常一样卸载。Slider 的碰撞箱足够大，如果它粘在一个一图块宽或高的方块上，你站在或抓住对侧时它都能杀死你。

Sliders 带两个参数。"Clockwise" 控制 slider 的移动方向。更重要的参数是 Face 参数，它决定房间加载时 slider 应附着到哪个表面。

在少数特定场景中，sliders 会尝试向下移动（相对而言，方向基于它们当前粘附在方块的哪一侧），直到到达一个可用表面。在这些情况中的每一种，如果找不到这样的表面，游戏就会崩溃。第一种场景是房间一加载就发生。第二种是 slider 所附着的方块不再实心时（例如 [Cassette Block](#cassette-block) 切换或 [Crumble Block](#crumble-block) 碎裂）。由于 sliders 不能正确地附着到移动方块上，如果任何移动物体移动得太快、slider 追不上，也会发生这种情况。
避免这些场景的最佳方法是将任何 Sliders 放在不移动、不变化的实心地面上，并确保在 Celeste 中加载关卡前仔细检查 Face 参数。如果任何移动物体有机会与 Sliders 互动，可以通过将它们用 Foreground Tiles 围起来、使 slider 永远不可能"坠落"而没有地方"着陆"，从而让整个系统防崩溃。不过在这种情况下，"坠落"效果意味着 Sliders 在某些情况下仍然会显得像瞬移。

![3 Sliders](https://github.com/user-attachments/assets/a5f7bbd9-5e3a-4437-ac2e-91afd48967e2)

### Sinking Platform

这些平台一旦站上去就会开始下落。当你跳起或滑落时，它会上升，直到回到原始位置或被再次激活。如果你在它上升时落地并立即跳离，会获得额外的垂直动量。

![sinking-platform](https://github.com/EverestAPI/Resources/assets/49392266/1838ca67-9679-411c-8224-5af82afb7611)

### Snowball

黄金山脊（Golden Ridge）最后一个子章节 Cliff Face 中那~~令人抓狂的~~障碍物。它们通过进入 [Snowballs](#wind) 触发器启用。它们在屏幕右边缘外 10 像素处生成，除非 Madeline 位于屏幕右边缘前 64 像素处。它们接触即死，除非玩家跳到它们顶上；这会摧毁雪球并让 Madeline 从它上面弹开。它们的运动并非完全水平，带有一丝非常细微的垂直正弦波运动。

![snowball](https://github.com/EverestAPI/Resources/assets/49392266/430ba548-cc5b-427a-b1e1-0d1c64a1eca8)

### Spikes

游戏中最常见的障碍物之一。用于覆盖本来安全的地面或墙壁。它们的碰撞箱从底座延伸 3 像素，所以尖端不会杀死玩家。如果你沿着尖刺朝向的同一方向移动，它们也不会杀死你。尽管它们在不同章节有不同的精灵图，碰撞箱都是相同的。它们会附着到移动实体上。

![spikes](https://github.com/EverestAPI/Resources/assets/49392266/91a83c6b-29b8-49d1-bc27-70b73e8ce0a9)

### Spring

玩家与它们互动时，会失去之前拥有的所有动量，并以设定的速度和方向弹跳。弹跳可以被冲刺打断，并会略微受到玩家方向输入的影响。它们会附着到移动实体上。

![spring](https://github.com/EverestAPI/Resources/assets/49392266/cf5e1a30-849e-4a6a-baae-6fd26921e851)

### Starjump Block

除了看起来很酷之外，如果你站在它们上面，它们会下沉一点，除非 "Sinks" 设为 false。如果两个互相接触，它们会在视觉上合并，但仍会分别移动。重叠的方块可能导致游戏崩溃。如果存在 Star Climb Controller 或 Star Climb Color Controller，它们内部会获得一种浅蓝色视觉效果（颜色可以用后者自定义）。

![starjump-block](https://github.com/EverestAPI/Resources/assets/49392266/d8e6b656-7f97-4522-987c-a349792287b7)

### Strawberry

你的普通有趣但无用的收集品。抓到草莓后，你必须落在"安全地面"（前景图块、大多数静止的实心物体或水）上至少 9 帧才能收集它。

如果带翅膀，草莓会在冲刺时向上飞，但在它们飞走时仍然可以被收集。
如果给它们添加节点，草莓种子就会出现。如果你在地面停留超过 9 帧，或在地面上跳跃或冲刺，你会失去携带的所有种子。（不过，你可以触地后在 9 帧内走开以保留它们。）如果所有种子一起收集齐，草莓本身会出现并保持存在直到被收集，即使玩家死亡。

如果勾选 Moon，它会变成第 9 章的隐藏 Moon Berry。不过这对带翅膀或带节点的草莓无效。

![strawberry](https://github.com/EverestAPI/Resources/assets/49392266/875035bd-d0f9-4b5b-b175-f5b89423c933)

### Strawberry Blockfield

如果玩家触碰到其中一个，即使站在其他安全地面上，也不会收集任何草莓。

![strawberry-blockfield](https://github.com/EverestAPI/Resources/assets/49392266/cc784ff7-e1f6-4541-bc89-a7061070d9e9)

### Summit Background Manager

这个实体管理 Summit 发射过场；当 Madeline 经过其垂直位置时（通常是在 [Badeline Booster](#badeline-boost) 的最终助推期间，否则动画可能看起来很奇怪），她会冻结在原地，发射场景开始。"Cutscene" 参数决定过场要播放哪条对话条目，如果参数留空或勾选 Intro Launch 框，则会跳过该过场。对于包含的过场，Badeline 总是会在发射序列中出现。"Ambience" 参数决定发射序列期间（及之后）的背景环境音，如果勾选 "Dark" 框，背景会变成第 9 章中看到的深色版本。序列结束时，玩家会自动进行房间中正上方的画面过渡。

> [!WARNING] 警告
> 如果玩家以未与图块网格对齐的 X 位置进入这段过场（可以通过放置一个对齐网格的 Badeline Booster 来避免），序列结尾的震动会纯粹依据 RNG 让 Madeline 对齐到两个相邻图块之一。
>
![summit-background-manager](https://github.com/EverestAPI/Resources/assets/49392266/2428aeff-bcbf-4135-9e98-64575ee05250)

### Summit Checkpoint

本质上，它们是美化版的屏幕中央出生点标记。玩家一站到它附近，它就会触发出生点更改，所以需要在每个附近放置 [Spawn Points](#player-spawn-point)。两个 Checkpoint 可以有相同的数字，但除非存在分支路径，否则没有意义。在它们的配置窗口中设置的数字就是游戏内显示的数字。建议只在不可能回头的情况下使用它们，因为每个只能激活一次。

![summit-checkpoint](https://github.com/EverestAPI/Resources/assets/49392266/924652fa-1fa5-4c91-bc8d-93a453d6aaac)

### Swap Block

这些方块在玩家使用冲刺时从原始位置移动到节点。它以每秒 360 像素的速度移动。它有 0.8 秒的超时，一旦完成超时，无论是否到达节点都会返回原始位置。再次冲刺会重置此超时。如果给定 swap block 的节点太远，它可能在到达节点前超时，意味着除非玩家再次冲刺（重置超时并给方块到达的时间），否则它无法到达。

"Theme" 参数仅影响视觉，但可能有用，因为 Normal 变体带有一大块背景贴图，如果没有完全放在背景图块补丁上方（还要留一点边距），看起来会很糟。

![swap-block](https://github.com/EverestAPI/Resources/assets/49392266/a4353c74-f54b-4798-b3d2-898bd0c37c3b)

### Switch Gate

一旦所有 [Touch Switches](#touch-switch) 被收集，这些门会移动到它们的节点，无视路径上任何实心物体。如果设置为 "Persistent"，所有 Touch Switches 保持已收集状态，Switch Gate 保持在它的节点处，即使在重生之后。它总是会在 2 秒（120 帧）内移动到节点。

![switch-gate](https://github.com/EverestAPI/Resources/assets/49392266/40b851f9-e72c-481f-8eb0-a988387cf54d)

### Temple Cracked Block

这些红色方块只有在 [Seeker](#seeker) 冲刺撞入时才能被破坏。如果设置为 Persistent，即使玩家死亡也会保持破碎。

![temple-cracked-blocks](https://github.com/EverestAPI/Resources/assets/49392266/5105296e-66ac-4ce8-bfb6-2b7590b80aa1)

### Temple Gate

这些门有不同的模式，各自行为略有不同。
- `CloseBehindPlayer`：一旦玩家到它右侧就关闭，重生后仍然保持关闭。
- `CloseBehindPlayerAlways`：一旦玩家到它右侧就关闭，但重生时打开。
- `CloseBehindPlayerAndTheo`：一旦玩家和 [Theo Crystal](#theo-crystal) 到它右侧就关闭，但重生时打开。
- `NearestSwitch`：最近的 [Dash Switch](#dash-switch) 被激活时打开。
- `TouchSwitches`：所有 [Touch Switches](#touch-switch) 被收集后打开。与 Persistent 结合时，即使重生后也保持打开。
- `HoldingTheo`：变为淡黄色，只在 [Theo Crystal](#theo-crystal) 附近时打开。常用于防止玩家在没有 [Theo Crystal](#theo-crystal) 的情况下到达屏幕尽头（游戏对此非常反感）。

所有 Temple Gates 的顶部都有一个仅视觉的黑色矩形标记。Temple Gates 有一个仅视觉的 Sprite 参数，Height 可以调整。不过，因为游戏并不真地预期这种情况发生，门精灵图不会延伸超过默认的 48 像素高度，所以任何更高的门都会有一个不可见的部分。不过这个参数偶尔仍可用于隐藏那个黑色矩形或制作非常小的门。

![temple-gate](https://github.com/EverestAPI/Resources/assets/49392266/5f86bb34-79ad-48e8-b8c3-7fe1ed378b30)

### Temple Mirror

Temple mirrors 是可调整大小的镜子，对游戏性没有影响。带两个参数，控制 Madeline 的倒影相对她实际位置会出现在镜子的哪里（如果两个都保持 0，Madeline 的倒影将不可见）。
由于镜子边框与镜背的深度差异，放置在镜子边缘上的贴花会被边框裁掉。

<img width="624" height="427" alt="Theo 出现在 Temple Mirror 中的镜之圣殿过场" src="https://github.com/user-attachments/assets/e88f37cc-89b5-429f-8d7a-ee298190b084" />

### Theo Crystal

Theo 进入镜子后的结果，展示了他的感受——被冻结在原地。玩家必须把水晶带到房间尽头才能继续。Theo 在 Crystal 内对 [Seekers](#seeker)（只会弹开）、[Spikes](#spikes) 和 [Spinners](#crystal-spinner-dust-bunny) 免疫。然而，如果他掉出屏幕或被挤压，他会死亡，这也会连累杀死玩家。持握水晶时，玩家会失去冲刺或贴墙的能力。Theo 还可以收集 [Touch Switches](#touch-switch)、按压 [Dash Switches](#dash-switch) 以及打开 `HoldingTheo` 模式的 [Temple Gates](#temple-gate)。

![theo-crystal](https://github.com/EverestAPI/Resources/assets/49392266/ec671502-93b2-4398-8fe2-ab8e643aea27)

### Touch Switch

这些开关只要触摸或足够接近就会激活。如果收集了某个屏幕中的每一个，要么 [Switch Gate](#switch-gate) 会被激活，要么 [Temple Gate](#temple-gate) 会打开。[Seekers](#seeker) 和 [Theo Crystals](#theo-crystal) 也可以激活它们。如果玩家用 [Feather](#feather) 飞行，touch switch 的碰撞箱会明显变大。

![touch-switch](https://github.com/EverestAPI/Resources/assets/49392266/23770f08-ed17-412b-b71c-7a236e678b3a)

### Trigger Spikes / Dust

覆盖着 trigger spikes 的表面在玩家接触过后会变得致命。一开始它是无害的，但如果玩家碰到它，一旦玩家离开其碰撞箱，它就会布满尖刺或灰尘。只要玩家站在里面就是安全的，因为它没有计时器。

> [!WARNING] 警告
> Trigger Spikes 看起来和普通尖刺非常像，所以要当心！如果你试图放置尖刺，但它们在应该对齐网格时看起来没对齐，你很可能正在放置 Trigger Spikes。
>
![trigger-dust](https://github.com/EverestAPI/Resources/assets/49392266/7c127fc2-48ad-41ad-a7da-9504a39ea241)

### Wall Booster / Ice Wall

当 Core 模式为 None 或 Hot 时，它们充当向上传送带，玩家抓住它们时会被自动向上移动。

当 Core 模式为 Cold，或实体设置了 "Not Core Mode" 时，它会变成一面冰墙，玩家无法抓住或从其攀爬跳离（不过仍然可以中立跳离）。如果玩家在墙冻结时已经抓着它，会继续保持抓住，但无法向上或向下攀爬。

![wall-booster](https://github.com/EverestAPI/Resources/assets/49392266/c08cc76b-1b28-4810-b28b-a5623001b5d0)
![ice-wall](https://github.com/EverestAPI/Resources/assets/49392266/f1fec4b2-3e95-40dc-a3ef-1c0a5509bb07)

### Watchtower / Binoculars

一副灰色的双筒望远镜，Madeline 可以与它互动，通过控制相机位置远程查看整个房间。通常，玩家可以向任何方向移动相机，只被房间边界（和 [Lookout Blockers](#lookout-blockers)）阻挡。如果启用了 Watchtower 的 "only Y" 参数，相机无法水平平移，无论房间形状如何。如果给 Watchtower 添加节点，相机会以完全不同的方式被控制：相机被锁定到由节点确定的路径上，依次访问每个节点。如果启用 Summit 参数，带节点的 Watchtower 到达最后一个节点时会放大到该节点，正如 Summit A 面最后 5 面旗帜的最后一个 Watchtower 中看到的那样。如果对不带节点的 Watchtower 启用 Summit 参数，玩家离开 Watchtower 时游戏会崩溃。

如果玩家掉落或被推落，可能提前被强制退出 watchtower 互动。如果玩家随后接触了某种赋予其移动能力的东西（即 [Spring](#spring)），这可能导致一个出故障的玩家状态。Watchtowers 也可以用来临时卸载 [Spinners](#crystal-spinner-dust-bunny) 或相关危险物。带节点的 watchtowers 不受房间边界约束，如果节点放得离边缘太近，可以显示房间外。

![Watchtower](https://github.com/user-attachments/assets/0842f0fa-69c7-4894-8311-8a62214b0c59)

### White Block

黄金山脊（Golden Ridge）A 面水晶之心谜题的核心组件。如果 Madeline 在这个平台上蹲伏连续 3 秒，她会掉下去穿过它。与此同时，当前房间中所有 Background Tiles 都会变成实心，只有房间重新加载或房间中不再有 [Crystal Heart](#crystal-heart) 实体时才停止实心。如果一开始就没有水晶之心，背景图块只会实心一帧。

### Water

虽然它的轮廓是动态的，但它有平整的碰撞箱。游泳时，玩家会无视所有重力和其他类型的加速度，所有方向输入的速度相同。如果在游泳时冲刺，会立即恢复冲刺，即使你冲刺并离开水也一样，除非水只有一个图块深。没有空气计，所以你可以无限期待在水下。它无视重力，所以任何放在空中的水都会停在那里。它们可以用 "Has Bottom" 选项获得底部表面，但不能有侧面。

![water](https://github.com/EverestAPI/Resources/assets/49392266/18d347c2-6c3a-4832-b423-89295dffb7ba)

### Waterfall

这些装饰性的细瀑布会从它们放置的 Y 位置向下延伸，直到撞到实心物体或 [Water](#water)。这个效果在房间加载时确定，不会改变，即使实心方块从 Waterfall 底部移开。Waterfalls 可以放置在天花板内最多 1 个图块的位置而不触发这种碰撞检查。

> [!NOTE] 说明
> 如果当前关卡中存在 "Heatwave" 风格地面效果，无论 Core 模式如何，瀑布看起来都会以不同的形状向上移动。实际上，这是一个极其细微的变化，但如果不知道原因，可能会让人困惑。
>
![waterfall](https://github.com/user-attachments/assets/ded2d3b1-e0e0-4e6c-99d4-21dedf53d915)

### Wire

Wire 是装饰性实体，是连接两点的细弧形线，会自然轻微摆动。它们可以重新着色。当存在 [Wind](#wind) 时，Wire 会对其作出反应，摆动得更剧烈——不过，由于一个疏忽，摆动被增强到了不合理的高水平，所以在可能出现 Wind 的地方应避免使用原版 Wire 实体。

![wire](https://github.com/user-attachments/assets/2c5860ce-10bf-4821-87a7-4f61941bf2a5)

### Zip Mover / Traffic Block

它们从原始位置移动到节点设置的位置，视觉上由拉索（zip line）标记，无视路上的所有东西，甚至 Foreground 图块。被激活时（通过抓住或落在顶部），无论距离多远，它们总是花费相同时间到达节点（0.5 秒/30 帧）；节点越远，走得越快。到达节点后，有 30 帧冷却，然后返回原始位置（历时 2 秒）。只有在返回原始位置并度过冷却后，它才会再次移动。

# 触发器

### Alt Music

工作方式与 [Music 触发器](#触发器) 相同，但改为设置 "Alt Music"。
Alt Music 是如果存在就替代普通 Music 播放的歌曲。不过，游戏不会"忘记"原音乐，并且如果 Alt Music 被关闭，不会从头重新开始原音乐。

### Ambience Param

为环境音设置一个参数，用于动态环境音，与 [Music Fade 触发器](#触发器) 非常相似。不过，很少有环境音有参数。
以下环境音具有可以通过 ambience param 触发器更改的参数：
`env_amb_03_interior`：basement 参数 [0-1] 增添水感。在约 0.9 时，它还会奇怪地偏向右声道。
`env_amb_04_main`：`shrine` 参数 [0-1] 让环境音（和风声噪音）平静得多。
`env_amb_06_main`：`postboss` 参数 [0-1] 让声音变得非常不祥。
`env_amb_09_main`：`progress` 参数 [0-3] 对应关卡中的区域（来自 fmod：外部、内部、过心门后、虚空房间）。

### Bird Path

如果此触发器存在于某个有 [Bird Path](#bird-path) 实体的房间中，该实体在玩家碰到此触发器之前不会开始其效果。这仅适用于实体 ID 最低的那个 Bird Path——其他都正常表现。如果同一房间中有多个 Bird Path 触发器，只有 Madeline 碰到的第一个会产生任何效果。

### Black Hole Strength

这个触发器负责 Farewell 中 Reconciliation 检查点过程中背景的变化。碰到此触发器会改变所有 "Blackhole" 风格地面效果的强度，从 Mild（默认）到 Wild。Wild 黑洞是鲜艳的粉色（相对于普通的紫色），移动更剧烈，并会获得额外的旋转粒子。由该触发器引起的黑洞强度变化生效缓慢，但如果玩家死亡会立即生效。

### Bloom Fade

与 [Light Fades](#light-fade) 工作原理相同，但它们影响的是 Bloom（光晕）而不是 Light（光照）。

### Camera Advance Target

它们与 Camera Target 的工作方式完全相同，但 Lerp Strength 和 Position Mode 可以分别针对 X 和 Y 方向设置。

### Camera Offset

此触发器强制相机移动指定数量的空间，使相机远离位于中心的玩家。Camera X 在 X 轴上移动相机，Camera Y 在 Y 轴上移动相机。值可以是任意数字，包括小数或负数。相机移动与值的比率为每 0.25 值偏移 1 个图块，也就是说值为 1 会将相机移动 4 个图块。相机不会移动超过屏幕边缘。此偏移在退出触发器后仍会保持，直到玩家死亡或过渡。

### Camera Target

此触发器会让相机朝触发器的节点移动。Lerp Strength 决定相机朝节点移动多少：为 1 时相机锁定在节点位置，为 0 时相机完全不变。
Position Mode 参数让 lerp 强度取决于玩家在触发器中的位置。如果位置模式是 None，无论玩家在触发器内的哪个位置，触发器总是使用 Lerp Strength 的值。但如果设置为 Left-To-Right，那么玩家在触发器左边缘时 lerp 为 0，在右侧时等价于 Lerp Strength 参数的设置。Horizontal- 和 Vertical- Center 选项让 lerp 在相关轴的中心最强。

只勾选 only-X 或 only-Y 会让相机只沿被勾选的轴移动。相机偏移在离开触发器时重置。

### Change Respawn

把玩家的出生点设置为距离触发器中心最近的 [Player](#player-spawn-point) 对象；如果触发器有节点，则为距节点最近的对象。

### Checkpoint Blocker

如果某个房间被设置为检查点，而玩家在此触发器内进入或重生，检查点不会激活。用于 Temple A 面 Theo 的基座房间。

### Credits

用于原版工作人员名单序列，在该过场之外没有用处。在该过场期间，它被用来向过场发出某些硬编码命令（例如 "Wait"）。

### Detach Followers

此触发器会分离任何跟随玩家的 [Strawberries](#strawberry) 并把它们移动到它的节点位置，过程中会发出锣的声音。跟随玩家的钥匙不受影响。被送到触发器节点的草莓会变为 Global，即使玩家死亡或离开/重新进入房间也会保持在那个位置。如果禁用 "Global" 选项，草莓在玩家离开房间后仍会保持，但死亡后不会。在这期间原始草莓实体仍会出现，所以草莓可以被"复制"，但收集时它们都仍算作同一个草莓，所以草莓计数不会超出应有的数量。
如果玩家带多颗草莓进入 detach follower 触发器，然后重新收集草莓并再次进入触发器，有时草莓会出现在错误的位置。

### Event

用于触发某些原版过场。这些过场都是硬编码的、无法更改，所以通常不建议使用它。此外，许多过场期望房间里存在某些物体（例如 end_city 过场需要一个 [Bonfire](#bonfire-campfire) 实体），如果该物体不存在会导致游戏崩溃。

这个实体可访问的事件中值得一提的有 `ch9_ding_ding_ding`，原版中放在金色房间的结尾。它只是播放一个音效，并用房间中第一个 `10-farewell/finalflag00` 贴花制造彩带。

事件 `ch9_goto_the_future` 和 `ch9_goto_the_past` 可以用作传送触发器（但需要名字非常特殊的房间 `intro-00-past` 或 `intro-00-future` 才能生效），不过传送应该使用模组替代方案。

### Golden Berry Collection

让玩家持有的任何 [Golden Strawberries](#golden-strawberry) 被收集。

### Light Fade

这些触发器做的正是它们名字所说的事：让光照淡出。设置时，Light Fade 指示进入触发器时要强制施加的光照淡出级别，Light Fade 指示退出触发器时的级别。两者都基于 0 到 1 的值（含小数），0 为全亮，1 为全暗。位置模式决定按什么顺序接收它所获得的信息，也就是说，如果位置相对于触发器的使用方式设置反了，它会工作不正确。

### Lookout Blockers

阻止 Watchtowers 滚过它。如果玩家在 Lookout Blocker 位于相机上方时进入 watchtower，watchtower 将完全无法移动。如果玩家足够快地接近 watchtower，相机的追赶运动可能意外导致这种情况发生。

### Mini Textbox

让一个带有指定对话 ID 的小文本框出现在屏幕顶部。如果 "Death Count" 设置为 -1，它总是会显示；否则，只有当玩家在当前房间死亡指定次数时才会播放。

"Mode" 决定显示文本框的条件：OnPlayerEnter 会在玩家碰到它时触发，OnLevelStart 会在进入房间时立即触发，OnTheoEnter 会在 [Theo Crystal](#theo-crystal) 碰到它时触发。"Only Once" 会让文本框每关只显示一次；否则，它可以在玩家每次死亡或进入房间时触发。

![mini-textbox](https://github.com/EverestAPI/Resources/assets/49392266/18afbcb9-36d2-4f5d-8907-49fd344b437c)

### Moon Glitch Background

让所有 Tag 设置为 "moon" 的风格地面在短时间内启用。如果启用 "Glitch"，这会伴随视觉和音频效果。具体时长由 Duration 参数决定。Stay 参数让相关风格地面在效果结束后保留。

### Music

用于更改一个屏幕的音乐。如果一个屏幕已经有音乐（从房间配置窗口设置），你身处其中时它会改变，然后恢复原状，除非禁用 "Reset On Leave"。

### Music Fade

与 [Light Fade](#light-fade) 工作原理相同，只不过它们允许动态音乐控制。玩家死亡时重置。

默认情况下，它们控制音乐的音量。不过，如果 "Parameter" 选项不是留空，也可以有其他行为。此选项对应 FMOD 中一个 Parameter 的名称（[此处有解释](https://github.com/EverestAPI/Resources/wiki/Advanced-Custom-Audio#understanding-parameters)，例如 "progress" 或 "layer1"），触发器会将参数在你指定的输入值之间变化。

### Oshiro (Spawn / Leave)

如果 "State" 设为 true，会让一个 [Oshiro Boss](#oshiro-boss) 生成。否则，会让一个已存在的 [Oshiro Boss](#oshiro-boss) 在完成当前冲锋后离开。如果存在多个 [Oshiro Bosses](#oshiro-boss)，只会有一个离开。

### Respawn Target

行为类似带节点的 [Change Respawn](#change-respawn)，但只在玩家于进入其所在房间的画面过渡期间碰到它时激活。解释一下为什么这有用：普通 Respawn Triggers 有一个不幸的行为——如果玩家在进入房间后的第一帧按暂停并重试，任何普通 Respawn Triggers 都没有时间"生效"，所以玩家可以有效地无视其效果，在可能对关卡预期流程造成问题的位置重生。Respawn Target 触发器不会发生这种行为，所以把它们放在预期出生位置不是离玩家进入点最近的那个的房间过渡上。

### Refills (Disabled / Enabled)

如果 "State" 设为 true，碰到它会禁用玩家在触地时恢复冲刺的能力。否则，它禁用这个效果。

### Rumble

进入此触发器会让触发器节点之间的所有 [Crumble Wall on Rumble](#crumble-wall-on-rumble) 实体崩塌。触发器只检查实体的水平位置——目标实体无论垂直位置如何都会崩塌。

### Snowballs / Wind Attack

进入此触发器会让 [Snowballs](#snowball) 开始以固定间隔出现。

### Spawn Facing

通常，Madeline 重生时总是面朝房间中心。当不希望这样时，可以把 Spawn Facing 触发器放在出生点上来覆盖此行为。

### Stop Boost

这些触发器会在玩家使用 [Badeline Boost](#badeline-boost) 的最终节点后停止其向上移动。如果玩家不进行画面过渡或碰到此触发器，她会继续上升并卡在屏幕外或任何实心物体的下方，迫使玩家重试。

### Wind Pattern

这些触发器在玩家进入时激活它们所设置的任何 [Wind](#wind) 模式。

### Wind

由触发器激活（说真的，它不是实体，但为了完整性列在这里），它会根据强度把玩家朝相反方向推。有 4 个方向：右、左、上、下。水平风与垂直风分开存储，所以两者可以同时激活（例如 Strong Left 加上 Up）。不过，"Windsnow" 和 "Stardust" 风格地面效果都无法显示对角风的效果。

> [!NOTE] 说明
> Wind 本身没有视觉或听觉效果。强烈建议用 "Windsnow" 或 "Stardust" 风格地面效果来向玩家指示风的存在。此外，关卡的环境音必须设置为 "env_04_main" 或 "env_10_voidspiral"，风才会发出声音。
> "Cliffside Big Flag" 实体和 "Blackhole" 风格地面效果也会受到风的影响，但这些通常不应成为关卡中风存在的唯一指示。
>
* **Left:**
  * Normal: 普通，40 像素/秒
  * Strong: 强，80 像素/秒
* **Right:**
  * Normal: 普通，40 像素/秒
  * Strong: 强，80 像素/秒
  * Crazy: 疯狂，120 像素/秒
* **Up:**
  * Normal: 普通，40 像素/秒
  * Space: 太空，60 像素/秒
* **Down:**
  * Normal: 普通，30 像素/秒
* **OnOff:** 始终使用 80 像素/秒（强）。
  * Normal: 每 3 秒切换一次。
  * Fast: 每 2 秒切换一次。
* **Alternating:** 始终使用 40 像素/秒（普通）。
  * 吹 3 秒风，暂停 2 秒，每次暂停后在左右之间切换。
* **LeftGemsOnly:** 如果玩家持有草莓种子，则以 40 像素/秒（普通）向左吹风。

## Everest 触发器
这些触发器内置于 Celeste 的模组加载器中——它们无需任何 "helper mods" 即可工作，但严格来说并非原版。

* Activate Dream Blocks — 无需 Dream Mirror 实体即可激活 Dream Blocks
* Ambience Volume — 更改环境音音量
* Ambience — 更改环境音
* Change Inventory — 更改 Inventory 元数据选项
* Complete area — 自动清空关卡
* Core Mode — 无需开关即可更改 Core 模式
* Crystal Shatter — 破坏房间中的所有 spinners
* Custom Bird Tutorial — 与 Custom Bird Tutorial 实体一起使用
* Custom Height Display — 显示山巅（The Summit）中的 "x meters" 文本框，使用自定义文本
* Dialog Cutscene — 使用你选择的对话键播放仅含对话的过场
* Flag — 设置一个 Flag
* Lava Blocker — 阻止 Rising Lava 或 Sandwich Lava 移动
* Music Layer — 打开或关闭一个音乐层
* Smooth Camera Offset — 相机偏移的一个变体，使用不同的平滑曲线
